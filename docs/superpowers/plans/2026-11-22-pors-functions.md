# PORS User-Defined Functions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Work in an isolated worktree, use TDD, commit each finished task, request review before merge.

**Goal:** Add top-level PORS functions with typed parameters, calls and returns that execute equivalently in the Rust backend and debugger VM.

**Architecture:** Precollect PORS function signatures, lower bodies/calls to typed shared HIR, compile HIR functions to VM frames and emit typed Rust functions. Keep `inicio` as the unique zero-argument void entrypoint and preserve the classic frontend.

**Tech Stack:** Rust workspace; `portugol-rs-frontend`; `portugol-hir`; `portugol-bytecode`; `portugol-vm`; `portugol-rust`; `portugol-service` tests.

**Spec:** `docs/superpowers/specs/2026-11-22-pors-functions-design.md`; product gate: `docs/adr/0016-pors-como-linguagem-autoral-e-retirada-do-por.md`.

## Global Constraints

- New syntax is `funcao nome(param: tipo) -> tipo { retorne expr; }`; `funcao inicio() { ... }` remains entrypoint.
- Five current scalar types are supported; function params are value semantics; generated Rust clones `cadeia` arguments.
- The normal backend remains generated Rust; debugger remains HIR-to-bytecode shared VM.
- Calls/returns preserve source spans and diagnostics; `inicio` remains no-args/no-return.
- No `.por` behavior, Tauri contract, product name, or extension changes in this feature.
- No commit/PR trailer for coauthorship or “Generated by”.

## Review Focus

- Forward/recursive call resolution: test signature collection before body lowering.
- Partial return paths: test `if` without `else` and loops do not count as guaranteed return.
- String value semantics: compare VM output and Rust output for repeated argument use.
- Debug call frames: pause inside nested helper and verify argument/local scope.
- Invalid return context/types: test exact diagnostic code and span before either backend runs.
