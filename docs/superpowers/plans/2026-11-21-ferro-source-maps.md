# Ferro-to-Rust Source Maps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Map generated Rust code and compiler diagnostics to trustworthy ranges in the originating `.por` or `.fer` document.

**Architecture:** Extend the shared HIR Rust emitter to return source map segments alongside generated Rust. Expose UTF-16 editor positions through the service, parse `rustc` JSON into typed compile outcomes, and use those mappings in the existing preview and diagnostics UI with stale-result guards.

**Tech Stack:** Rust workspace, serde/serde_json, Tauri 2 commands, TypeScript, CodeMirror 6, Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-21-ferro-source-maps-design.md`

## Global Constraints

- Keep original source offsets as UTF-8 byte offsets in Rust and convert to UTF-16 editor offsets at the service boundary.
- `exact` only applies to direct HIR spans; `approximate` is labeled; `generated_only` never navigates to source.
- A compile rejection is a typed IPC result variant, not a transport failure.
- Use fixed `rustc` invocation; no shell, Cargo, or arbitrary `.rs` execution.
- Stale export/run results are discarded when the active tab or source document changes.
- Preserve classic Ferro runtime behavior and existing export/detach semantics.

## Review Focus

- Unicode before or inside a mapped span: pin UTF-8 to UTF-16 conversion in service tests.
- Nested mappings: pin smallest-enclosing selection and deterministic order in codegen tests.
- Rustc diagnostic without a primary span: pin `generated_only` fallback and raw detail retention.
- Malformed or future rustc JSON fields: pin safe parsing without panics or lost stderr.
- Tab/document change during async export or run: pin complete stale-response discard in frontend tests.

**Interfaces:**
- Replace the run struct with a serde-tagged `FerroRustRunResult::{Executed, CompileError}`.
